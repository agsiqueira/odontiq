# Final independent knowledge candidate

The durable-evidence contract in repair-2 and the positive-requirement/consent corrections in repair-4 remain. Repair-4's 21 PASS / 1 FAIL run remains unchanged. Its remaining failure was the added split-turn control, not any of the four original PR findings.

Explanations are now allowed in Case 3's initial event stage as well as after the first question. Their presence does not imply an active treatment proposal, consent or follow-up confirmation. The independent explanation verifier runs even when trigger JSON is invalid. Validated knowledge may persist with a valid final response in that situation, but `questionDecisionVerified=false` prevents the failed trigger from selecting or consuming any question. A separate regression covers this path. HTTP/provider failures still leave the question available, and final validation still rolls back both knowledge and emission atomically.

The prior two-model candidates and their probes showed unsupported cross-fact quotations from the explanation verifier. The final dedicated verifier uses Navigator `gpt-oss-120b` (default or `NAVIGATOR_EXPLANATION_MODEL`), while patient generation and the existing trigger classifier remain `granite-3.3-8b-instruct`. The provider's internal task override does not come from public request input. Six critical boundary probes are preserved under repair-4/oss-independent-probes.json. This is an explicit, reviewable model/configuration change, not a silent repeat on the same behavior.

The current-message-only verifier returns independently typed temporary-effect and positive-definitive-requirement decisions. Each accepted positive fact requires a verbatim source witness and confidence >=0.85. A false decision, including a quoted counterexample, supplies no evidence and cannot suppress Why; its unused quote is not persisted. Missing/invalid schemas, out-of-range confidence, invented positive quotes, low-confidence positive facts and provider errors still fail closed. No known failed item is regraded or removed. No accepted clinical-utterance dictionary is introduced.

The dedicated verifier has a 2048-token budget to accommodate the model's reasoning and final structured output, under the existing Navigator timeout and bounded 502/503/504 transport retry policy. No validation failure is retried until it happens to pass. The stronger model introduces latency and availability dependence; the production key's access to this model must be confirmed before a separately authorized deployment. The local key's model access was actually tested.

No schema migration, case facts, faculty specifications, patient-question texts, authentication flow or speech changes. Existing legacy event booleans are not treated as validated explanation witnesses. Existing encounters without those new witnesses are not silently backfilled from unverified flags. The interrupted historical Clerk session remains untouched; each completed new test run revokes only the precise session it created.
